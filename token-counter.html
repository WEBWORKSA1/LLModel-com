What a token is

A tokenizer breaks text into pieces from a fixed vocabulary, usually built with byte-pair encoding: the most frequent character sequences in the training data become single tokens. That's why "the" is one token while "tokenization" might be two or three, and why a long number can take one token per few digits.

Tokens matter for three reasons. They set the price, since APIs bill per million input and output tokens. They set the limits, because a model's context window and maximum output are measured in tokens. And they explain some odd behavior, like models miscounting letters in a word they see as one or two tokens.

Rules of thumb for English

  • 1 token is about 4 characters or three quarters of a word.
  • 100 tokens is about 75 words; a dense page of 500 words is roughly 650-700 tokens.
  • Code, JSON, URLs and non-English text usually take more tokens per character.
  • Spaces belong to the following word, so " cat" and "cat" can be different tokens.

Frequently asked questions

How many tokens is a word?

In English, a token averages about three quarters of a word, so 100 words is roughly 130 tokens and 1,000 tokens is about 750 words. Short common words are usually one token; long or rare words split into several. Other languages, code and numbers often use more tokens per word.

Do all models count tokens the same way?

No. Each model family has its own tokenizer, so the same text can produce noticeably different counts on different models. The exact count here uses OpenAI's o200k tokenizer; treat counts for other providers as estimates and check their own token-counting tools for billing-grade numbers.

Is my text uploaded anywhere?

No. Counting happens in your browser. The exact tokenizer is a JavaScript file downloaded from a public CDN; your text stays on your device.

Why does the cost table only price input?

Because the text you paste is what you'd send. The response is billed separately as output tokens, usually at several times the input rate. Use the cost calculator to price both sides of a full workload.
