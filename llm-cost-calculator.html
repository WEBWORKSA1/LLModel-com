      How the calculator works

      For each model, the cost of one request is the input tokens times the input price plus the output tokens times the output price, divided by one million because prices are quoted per million tokens. Cached input replaces part of the input price with the cheaper cached rate. The monthly bill multiplies that by requests per day and days per month.

      cost per request = (input × (1 − cache share) × input price
                    + input × cache share × cached price
                    + output × output price) ÷ 1,000,000
monthly cost     = cost per request × requests per day × days

      A worked example

      A support bot handles 1,000 conversations a day. Each request sends 2,000 input tokens and gets 400 back. On a model priced at $2 per million input tokens and $10 per million output tokens, one request costs (2,000 × $2 + 400 × $10) ÷ 1,000,000 = $0.008. Over 30 days that's 30,000 requests, or $240 a month. The same workload on a model at $0.10 and $0.50 costs $12.

      Five ways to cut the bill

      • Route by difficulty. Send routine requests to an efficient model and escalate only the hard ones.
      • Cache the stable part of your prompt. Put system instructions and shared documents first so providers can cache them.
      • Trim the context. Retrieve the three most relevant passages instead of sending the whole manual.
      • Batch what can wait. Overnight summaries and evaluations rarely need real-time answers.
      • Cap output. Ask for concise, structured answers and set a maximum token limit.

      The full picture, including reasoning tokens and long-prompt surcharges, is in LLM API pricing explained. If you're paying for GPUs instead of tokens, try the self-host vs API calculator.

      Frequently asked questions

      How do I estimate tokens per request?

      Count everything you send: system prompt, conversation history, retrieved documents and the user's message. For English text, 1,000 tokens is roughly 750 words. Paste a real prompt into the token counter to measure it, and remember that output tokens include any reasoning tokens the model generates.

      Why is output priced higher than input?

      Output tokens are generated one at a time, each needing a full pass through the model, while input tokens are processed in parallel. Providers price output at several times the input rate to reflect that cost.

      What is cached input?

      When you resend the same prompt prefix, such as a long system prompt or document, many providers bill the repeated part at a discounted cached-input rate. The slider applies each model's published cached price to the share of input you expect to repeat.

      Does this include taxes, long-prompt surcharges or regional pricing?

      No. It uses standard list prices. Some providers charge more for prompts above a size threshold, for priority processing or for regional data handling; the model pages note these where they apply.
