The anatomy of a strong prompt

Most weak prompts fail for the same reason: the writer knows things the model doesn't. The builder walks you through the parts that close that gap.

  • Task. One clear instruction with a verb: summarize, extract, rewrite, review, decide.
  • Context. Who it's for, why it matters, what you'll do with the answer and what a great result looks like.
  • Input. The material to work on, fenced off with tags so it can't be confused with instructions.
  • Format. The exact shape you want back. For anything a program will read, ask for JSON with named fields.
  • Rules and an example. Constraints the model can check itself against, and one good answer to imitate.

Then test it: run the prompt on five real inputs, note where it goes wrong, and add a rule or example for each failure. Our prompt engineering guide covers techniques, reasoning models and versioning.
