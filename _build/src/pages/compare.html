How to read a comparison

Specs tell you what a model can accept and what it costs at list price. They don't tell you how well it does your job. Use this table to rule models out (too expensive, too little context, wrong license, no image input), then test the two or three that remain.

Prices

Input and output tokens are billed separately, and output usually costs several times more. Cached input, which providers charge when you resend the same prompt prefix, can be far cheaper than normal input. Batch processing often halves the bill for work that can wait. The workload rows below the specs apply list prices to three common token mixes so you can see the gap in dollars, not just per million tokens.

Context and output limits

The context window caps how much text you can send in one request, including conversation history and documents. Max output caps one response. A model with a huge window but a small output limit can read a book and still need several calls to write a long report.

Weights and license

Closed models run only on the provider's servers or their cloud partners. Open-weight models can also run on your own hardware, which matters for data residency and steady high volumes. Read the license before you build a product on an open model: some cap revenue or restrict serving the model to others. Our guide to open-source vs closed LLMs explains the trade-offs.

Then test

Run 20 to 50 representative tasks through each finalist with identical prompts. Score the answers, note latency, and divide each model's bill by its number of correct answers. That cost per correct answer is the number to decide on. How to read LLM benchmarks covers building a small evaluation set.
